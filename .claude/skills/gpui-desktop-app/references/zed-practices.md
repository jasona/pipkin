# What Zed does (read from source, rev a846890) and why it is fast

Verified by reading; items marked (inference) are not proven. `zed/.rules` is Zed's own coding rules file.

- **Single foreground thread, background for work.** Entities and UI on the foreground; `background_spawn` for parsing, highlighting, I/O. Foreground executor ignores priority; background has `RealtimeAudio/High/Medium/Low` (not strict).
- **Frame loop is demand-driven.** The compositor frame callback drives drawing; `draw` runs only if the invalidator is dirty or forced (G/window.rs:1709-1850). Dirtiness propagates to ancestor views only. Input at ≥60 Hz sustains presentation for 1 s; unfocused windows and thermal states throttle frames. Don't `notify` the whole window for a token; notify the streaming entity.
- **View caching** (`Entity::cached`) only on large panels (dock, pane group); everything else re-renders its subtree each frame and relies on cheap render + the line-layout cache. (G/view.rs, workspace/dock.rs:1364)
- **Never parse in render.** Markdown is an entity (`Entity<Markdown>`) created in the model layer; the list renders from its parsed events (acp_thread.rs:1378). Highlights are computed in the background and reused by pointer-equality.
- **Lists keep per-entry child entities** (`EntryViewState`: message editors etc., synced in place) and use `list` with Tail follow; `EntryUpdated` → `remeasure_items`, `NewEntry` → `splice_focusable`, `EntriesRemoved` → `splice` (conversation_view.rs:1822).
- **Text layout cache** is two-frame (`LineLayoutCache`), keyed by (text, size, runs, wrap width); cached views replay previous layouts. `shape_line_by_hash` avoids building a contiguous string when you already have a hash.
- **GPU selection** is empirical: sort by `ZED_DEVICE_ID`, then the compositor's GPU, then Discrete>Integrated>…, Vulkan first; then actually try to configure the surface per adapter (hybrid GPUs lie), skip CPU adapters. Present mode prefers Mailbox (falls back to FIFO) on Wayland. wgpu instance is `VULKAN | GL` only. On our machine it picked the Intel iGPU (the compositor's GPU) over the RTX.
- **Wayland windows are created `transparent: true`**; the opaque region is only set when `background_appearance == Opaque && decorations == Server` (CSD windows are always transparent for rounded corners/shadows). (inference for our see-through captures: Omarchy's default window-opacity rule plus a transparent surface; we did not isolate which.) Fractional scale via `wp_fractional_scale_v1` + `wp_viewporter` (scale in 1/120).
- **Profiling:** `profiler` cargo feature (Zed enables it everywhere) gives frame journals, `dev::ToggleFpsOverlay` debug overlay (paints raw quads, bypassing layout/invalidation so it can't trigger frames), hang monitor; `ZED_MEASUREMENTS=1` prints `measure()` timings (`window.draw` is wrapped as "frame duration"); `profiling::scope!` hooks; inspector available in debug builds. There is no frame-profiling xtask.
- **Tests:** `#[gpui::test]` (`retries`, `iterations`, `SEED`), `TestAppContext`/`VisualTestContext` (`simulate_keystrokes/input`, `simulate_mouse_*`, `simulate_resize`, `debug_bounds` needs `.debug_selector` and debug assertions), `run_until_parked`, `skip_drawing`, `disable_accessibility`, platform prompt simulation (`simulate_path_prompt_response`). Leak detection: `leak_detector_snapshot()` / `assert_no_new_leaks()`.
- **Don't** `unwrap()`; don't `let _ =` fallible calls; mutually recursive strong entity handles leak.
