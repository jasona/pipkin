# Native subagents in the bundled Pi engine

The pinned Pi revision `d2a311097cbcf669e699479587332ae3988a49d0` has a durable `Subagent` tool and child conversations, but its experimental session worker neither installs the tool nor exposes child state over the service transport. `scripts/build-engine.sh` now applies the reviewed `../pi-subagents.patch` and these first-party service files **by default** to clean pinned engine archives, never to the owner's Pi checkout. `PIPKIN_ENGINE_DEV=1` stages a development checkout as-is; subagents there depend on that checkout. The feature is enabled by default on the bundled engine and can be disabled per session in Preferences. Unqualified edge cases below remain, and are not presented as verified.

`pi-subagents.patch` registers the durable tool in the session worker, adds `pi.subagents` as a session service, and records the unwrapped tool's installed extension and public registration contract at its execution intent. On recovery, a recorded replay-safe subagent call may resume from the still-installed extension even when the root has since disabled new calls; removed registrations, changed replay policies, and replacements with different public contracts fail closed. Other tools continue to use Pi's existing deselection behavior. The two TypeScript files here define and provide the service; `experimental-subagents.test.ts` is a source-tree test, not a packaged runtime dependency. The service currently offers a durable child directory (`list`), live task graph (`activity`), selected child snapshot and history (`view`, `page`), lazily mounted live child transcript (`open` + keyed `pi.subagent-transcript`), and a persisted root-conversation tool choice (`setEnabled`). Each live child mount is shared across clients and kept until session-worker retirement; a bounded limit of 64 mounts prevents unbounded view retention. Pipkin's draft adapter now falls back to a snapshot when the keyed subscription is unavailable and labels it as such. It only lists task-owned children created by `subagent` tool calls in this session's root, validating the owner task and parent call before disclosing a child view.

## Qualification so far

- Changes were made in a disposable clone of the clean pin, not the owner's dirty Pi checkout.
- With Pipkin's identified generated model snapshot restored, the isolated clone passes `npm run check` (format, lint, TypeScript, dependency and import checks).
- Applying the existing onboarding patch followed by `pi-subagents.patch` passes `git apply --check` on an archive of the clean pin. The default clean-pinned engine was staged in `/tmp`, its `pipkinSubagentsSha256` verified against all three overlay inputs, and `--diagnose --probe` returned ready. A production-pruned stage (`productionPruneSucceeded: true`) also passed its probe and the service/adapter setting conformance tests against a local, offline throwaway server with a short socket path. Full installable-tarball and native UI tests remain unverified.
- Ran `npm run check`, rebuilt the isolated `durable` package, and ran focused Vitest files: 11 durable tool-recovery tests and 4 coding-agent service/plugin tests passed. These include disabled-on-restart recovery, removed/replaced registration refusal, disabling future calls, live child status and keyed transcript publication, completed child listing, child history/view isolation, and persistent toggle. No paid provider was used.
- Pipkin has guarded core events and commands, an optional session-service adapter, an inspector showing current child status and a bounded read-only transcript preview, and a per-session engine-authoritative preference. Against a throwaway server running a staged engine, both service conformance and the adapter's attach/setting round trip passed. `cargo test --workspace`, Clippy and formatting passed. The native UI, full child-history paging, real streaming, and packaged engine still require independent qualification.

## Known limitations and outstanding qualification

1. Recovery checks the public registration contract and replay policy; removed registrations and altered descriptions/policies are tested. Identical-contract code replacement, extension wrappers and broader plugin/recovery combinations are **not** proven equivalent and still need a stronger provenance mechanism before claiming full recovery safety.
2. A keyed/live child transcript is now tested for initial subscribe and updates on abort; test long streaming updates, multiple clients, mount limit fallback, and terminal-history pagination before claiming full drill-down coverage.
3. Test that concurrent child creation, cancellation, restart, plugin reload, and non-subagent task-owned conversations are presented correctly. Bound/paginate scans for large sessions and handle streaming updates without polling during rendering.
4. Qualify the current-session inspector and Preferences on native GPUI/AT-SPI, remove the 100-child and latest-80-entry preview limits with virtualized, paginated history, and verify reconnect, streaming, multiple clients, and stale child requests through the adapter. Add packaged/offline tests and prove the manifest and service match. On external engines the UI presents subagents only when the attached engine supplies the service.
